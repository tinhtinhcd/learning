# 1. Object Memory Layout Deep Dive

A Java object typically contains:

```text
Object Header
Instance Fields
Padding
```

Object size depends on:

- JVM architecture
- Compressed Oops
- Memory alignment

---

# 2. Compressed Oops

## Problem

64-bit references consume significant memory.

## Solution

Compressed Oops reduce reference size from 8 bytes to 4 bytes in many situations.

Benefits:

- Lower memory footprint
- Better cache efficiency
- Improved performance

---

# 3. Object Alignment

JVM aligns objects to memory boundaries.

Typically:

```text
8-byte alignment
```

Benefits:

- Faster CPU access
- Better cache utilization

---

# 4. Java Lock States

```text
Biased Lock
 ↓
Lightweight Lock
 ↓
Heavyweight Lock
```

Each state is optimized for different contention levels.

---

# 5. Biased Locking

Optimized for single-thread access.

Advantages:

- Minimal synchronization overhead

Historical interview topic.

---

# 6. Lightweight Locking

Uses CAS operations.

Benefits:

- Avoids OS mutexes
- Lower overhead than heavyweight locks

---

# 7. Heavyweight Locking

Used when contention becomes significant.

Costs:

- Blocking
- Context switching
- Reduced throughput

---

# 8. Safepoints

A safepoint is a JVM state where all application threads can be paused safely.

Examples:

- Garbage Collection
- Heap Dump
- Deoptimization

---

# 9. Stop-The-World (STW)

During STW:

```text
Application Threads Pause
```

Impact:

- Increased latency
- Reduced throughput

---

# 10. On Stack Replacement (OSR)

Allows JVM to replace interpreted code with compiled code while a method is already running.

Benefits:

- Runtime optimization
- Better performance for long-running loops

---

# 11. Deoptimization

JVM may revert optimized machine code back to interpreter execution.

Reasons:

- Assumptions become invalid
- Runtime behavior changes

---

# 12. Code Cache

Stores machine code generated by JIT.

Potential issue:

```text
Code Cache Full
```

Can reduce performance.

---

# 13. Native Memory Tracking (NMT)

Tracks native memory allocation.

Enable:

```bash
-XX:NativeMemoryTracking=detail
```

Inspect:

```bash
jcmd PID VM.native_memory summary
```

---

# 14. Direct Memory Deep Dive

Example:

```java
ByteBuffer.allocateDirect()
```

Benefits:

- Faster I/O operations

Risk:

```text
OutOfMemoryError: Direct buffer memory
```

---

# 15. ClassLoader Memory Leak

Common production issue.

Typical causes:

- Static references
- Improper application reloads
- Custom ClassLoader misuse

Result:

```text
Metaspace Growth
```

---

# 16. JVM Startup Parameters

Heap:

```bash
-Xms2g
-Xmx2g
```

Metaspace:

```bash
-XX:MetaspaceSize=256m
-XX:MaxMetaspaceSize=512m
```

GC:

```bash
-XX:+UseG1GC
```

Heap Dump:

```bash
-XX:+HeapDumpOnOutOfMemoryError
```

# 17. Container Awareness

# 18. Memory Leak Investigation Workflow

1. Observe memory growth
2. Generate Heap Dump
3. Analyze with MAT
4. Identify retained objects
5. Fix root cause

---

# 19. High CPU Investigation Workflow

Tools:

```bash
top -H
jstack
```

Steps:

1. Find busy thread
2. Capture thread dump
3. Analyze stack traces
