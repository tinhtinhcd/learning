# Part II. Index Deep Dive

## B-Tree vs B+Tree

B+Tree advantages:

- Better range scans
- Sequential leaf nodes
- Fewer disk reads

### Example

```sql
CREATE INDEX idx_user_email
ON users(email);
```

## Clustered vs Non-Clustered Index

Clustered:

- Data stored in index order
- Only one per table

Non-Clustered:

- Separate structure
- Multiple per table

## Composite Index

```sql
CREATE INDEX idx_order
ON orders(customer_id, status, created_at);
```

Left-most Prefix Rule:

Works:

```sql
WHERE customer_id=?
```

Usually not optimal:

```sql
WHERE status=?
```

## Covering Index

A query can be served directly from the index.

Benefits:

- No table lookup
- Faster performance

## Index Selectivity

High selectivity indexes are usually more effective.
